    Single Responsibility Principle (SRP) ✅
    ┌────────────────────────────────────────────────────────────────────┐
    │ Each function has a single, well-defined responsibility:           │
    │ • _check_timeout_remaining: Timeout checking only                    │
    │ • _get_next_chunk_with_timeout: Chunk retrieval only                │
    │ • _process_chunk: State processing only                              │
    │ • _emit_progress_if_needed: SSE emission only                       │
    │ • _cleanup_stream: Resource cleanup only                            │
    │ • stream_agent_response: Orchestration only                         │
    └────────────────────────────────────────────────────────────────────┘

    Open/Closed Principle (OCP) ✅
    ┌────────────────────────────────────────────────────────────────────┐
    │ • Helper functions are extensible without modification              │
    │ • New timeout strategies can be added via new helpers                │
    │ • Core logic remains unchanged when extending                       │
    └────────────────────────────────────────────────────────────────────┘

    Liskov Substitution Principle (LSP) ✅
    ┌────────────────────────────────────────────────────────────────────┐
    │ • All helper functions maintain expected behavior                   │
    │ • No breaking changes to function contracts                        │
    │ • Return types and exceptions are consistent                        │
    └────────────────────────────────────────────────────────────────────┘

    Interface Segregation Principle (ISP) ✅
    ┌────────────────────────────────────────────────────────────────────┐
    │ • Functions have minimal, focused interfaces                      │
    │ • No forced dependencies on unused functionality                    │
    │ • Parameters are only what's needed                                │
    └────────────────────────────────────────────────────────────────────┘

    Dependency Inversion Principle (DIP) ✅
    ┌────────────────────────────────────────────────────────────────────┐
    │ • Depends on abstractions (Runnable, AnalysisID)                   │
    │ • Uses dependency injection (logger, error handlers)               │
    │ • No direct dependencies on concrete implementations               │
