# Redis Caching Integration for SkillForge Backend

## Overview

Redis caching has been integrated into three critical areas of the SkillForge backend to reduce LLM costs and improve response times:

1. **Agent Execution** - Semantic caching for agent LLM responses
2. **Supervisor Routing** - Exact-match caching for agent selection decisions
3. **G-Eval Scoring** - Two-layer caching (file-based + Redis semantic)

## Architecture

### Caching Strategy

```
┌─────────────────────────────────────────────────────────────┐
│                     Redis Caching Layers                    │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  1. Agent Execution (Semantic Cache)                        │
│     • Similar content → Similar analysis                    │
│     • Distance threshold: 0.08 (92% similarity)             │
│     • TTL: 24 hours (configurable)                          │
│                                                              │
│  2. Supervisor Routing (Exact Cache)                        │
│     • Identical content → Identical agent selection         │
│     • TTL: 1 hour (configurable)                            │
│     • Deterministic routing                                 │
│                                                              │
│  3. G-Eval Scoring (Hybrid Cache)                           │
│     • L1: File-based (exact match, fast)                    │
│     • L2: Redis semantic (similar content)                  │
│     • TTL: 24 hours (configurable)                          │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

## Implementation Details

### 1. Agent Execution

**File**: `backend/app/core/model_factory.py`

**Integration Point**: Model factory level (automatic for all agents)

```python
def _get_redis_cache_for_model():
    """Get Redis semantic cache for LLM responses."""
    try:
        from app.shared.services.cache import get_semantic_cache
        cache = get_semantic_cache()
        return cache
    except Exception:
        # Gracefully handle Redis failures
        return None

# In get_chat_model():
redis_cache = _get_redis_cache_for_model()
if redis_cache is not None:
    init_kwargs["cache"] = redis_cache
```

**Benefits**:
- Zero code changes in agent implementations
- Automatic semantic matching via OpenAI embeddings (text-embedding-3-small)
- Graceful degradation if Redis is unavailable
- Cache hits logged for observability

**Cache Key**: Generated by LangChain from prompt + parameters

**Expected Hit Rate**: 40-70% for similar content patterns

### 2. Supervisor Routing

**File**: `backend/app/domains/analysis/workflows/nodes/supervisor.py`

**Integration Point**: Before and after supervisor decision

```python
def _generate_supervisor_cache_key(content: str, content_type: str) -> str:
    """Generate cache key from content hash."""
    content_hash = hashlib.sha256(
        f"{content[:3000]}{content_type}".encode()
    ).hexdigest()[:16]
    return f"supervisor:{content_type}:{content_hash}"

# Check cache
cached_value = await exact_cache.aget(cache_key)
if cached_value:
    cached_decision = json.loads(cached_value)
    return {"supervisor_decision": cached_decision}

# Store decision
await exact_cache.aset(cache_key, json.dumps(supervisor_decision))
```

**Benefits**:
- Instant routing decisions for repeated content
- Deterministic agent selection (same content = same agents)
- Lower latency (< 10ms vs ~1-2 seconds for LLM call)

**Cache Key**: SHA256 hash of first 3000 chars + content type

**Expected Hit Rate**: 20-30% (duplicate submissions, testing)

---

### 3. G-Eval Scoring

**File**: `backend/app/shared/services/g_eval/scorer.py`

**Integration Point**: Two-layer caching strategy

```python
# L1: File-based cache (exact match)
cached = file_cache.get(input_content, output, agent_type, criterion)
if cached:
    return cached  # Fast local lookup

# L2: Redis semantic cache (integrated at model level)
model = get_chat_model(task_type="g_eval")  # Has Redis cache
response = await model.ainvoke(messages)

# Store in L1
file_cache.set(...)  # For future exact matches
```

**Benefits**:
- Best of both worlds: exact match speed + semantic matching
- File-based cache survives Redis restarts
- Redis cache provides fuzzy matching for similar evaluations
- Cost savings: ~70-80% LLM call reduction

**Cache Key (L1)**: Hash of input + output + agent_type + criterion
**Cache Key (L2)**: Generated by LangChain from prompt

**Expected Hit Rate**: 60-80% combined (L1 + L2)

## Configuration

All Redis caching settings are in `backend/app/core/config.py`:

```python
REDIS_URL: str = "redis://localhost:6379/0"
REDIS_SEMANTIC_CACHE_TTL: int = 86400  # 24 hours
REDIS_EXACT_CACHE_TTL: int = 3600      # 1 hour
REDIS_SIMILARITY_THRESHOLD: float = 0.08  # 92% similarity
```

## Observability

All cache operations are logged with structured logging:

```python
# Cache hits
logger.info("agent_cache_hit", agent_type=..., cache_key=...)
logger.info("supervisor_cache_hit", analysis_id=..., agents=...)
logger.debug("g_eval_file_cache_hit", criterion=..., agent_type=...)

# Cache misses (implicit - no special log)

# Cache failures
logger.warning("redis_cache_unavailable", error=..., fallback=...)
logger.warning("supervisor_cache_set_failed", error=...)
```

## Error Handling

**Graceful Degradation**: All Redis cache operations are wrapped in try-except blocks. If Redis is unavailable:

1. **Agent Execution**: Falls back to no caching (normal LLM calls)
2. **Supervisor Routing**: Falls back to LLM routing (no cache)
3. **G-Eval**: Falls back to file-based cache only (L1)

**No workflow disruptions** - Redis failures are logged but don't break analysis.

## Cost Savings Estimation

Assuming:
- Average LLM call cost: $0.02
- Average analysis: 5 agents + 1 supervisor + 4 G-Eval criteria = 10 LLM calls
- 50% cache hit rate (conservative)

**Cost per analysis**:
- Without cache: 10 × $0.02 = $0.20
- With cache (50% hit): 5 × $0.02 = $0.10
- **Savings: 50% ($0.10 per analysis)**

For 1,000 analyses/day: **$100/day savings** = **$36,500/year**
